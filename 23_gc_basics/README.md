# GCの基本

Goは並行動作するトライカラーマーク&スイープ方式のガベージコレクタを採用しています。
runtime.GC()で手動でGCサイクルを実行でき、runtime.MemStatsからGCの統計情報を取得できます。

# トライカラーマーキング

GCはオブジェクトを白、灰、黒の3色に分類して到達可能性を判定します。
白はまだ走査されていないオブジェクト、灰は走査途中のオブジェクト、黒は走査完了のオブジェクトを表します。
ルートオブジェクトから開始して灰色のオブジェクトを順次走査し、灰色がなくなった時点で残った白色オブジェクトを回収します。

# STWフェーズ

GCサイクルには2回の短いstop-the-world(STW)フェーズがあります。
最初のSTWフェーズではライトバリアを有効化し、並行マーキングの準備を行います。
2回目のSTWフェーズではマーキング完了後にライトバリアを無効化し、最終的なクリーンアップを実行します。
2つのSTWフェーズの間では、マーキングがアプリケーションのゴルーチンと並行して動作します。

# アロケーションとGC実行

AllocateAndCollect関数は、n個のオブジェクトをヒープに確保してからruntime.GC()を呼び出します。
その後、runtime.MemStatsからNumGC(完了したGCサイクル数)を読み取って返します。

# ファイナライザ

runtime.SetFinalizerを使うと、オブジェクトが回収される際に呼ばれるコールバックを登録できます。
FinalizerDemo関数では、ヒープ上のオブジェクトにファイナライザを設定してからGCを実行しています。
ファイナライザは専用のゴルーチンで実行されるため、呼び出しタイミングは保証されません。

# GC統計情報

GCStats関数はruntime.ReadMemStatsを呼び出し、NumGC、PauseTotalNs、HeapAllocを含むスナップショットを返します。
NumGCは完了済みのGCサイクル数、PauseTotalNsは累計STW停止時間、HeapAllocは現在のヒープ割り当て量を表します。
