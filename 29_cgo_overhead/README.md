# cgoのオーバーヘッド

cgoはGoからC言語の関数を呼び出すための機能ですが、呼び出しごとに大きなオーバーヘッドが発生します。このパッケージでは実際のcgoは使用せず、純粋なGoコードでオーバーヘッドの概念を説明しています。

# cgo呼び出しが高コストな理由

cgo呼び出しでは以下の5つの要因がオーバーヘッドを生みます。

第一に、ゴルーチンがCのコードを実行する間はOSスレッドに固定されます。Goスケジューラはそのスレッドに他のゴルーチンを割り当てられなくなります。

第二に、Goのゴルーチンスタック(数KB)からCが必要とするシステムスタック(通常8MB)へのスタック切り替えが発生します。

第三に、C関数の実行中はGoのガベージコレクタがメモリを移動できません。Cに渡すGoポインタは固定する必要があり、GCはC呼び出しの完了を待つ必要があります。

第四に、C関数の実行中はGoスケジューラがゴルーチンをプリエンプションできません。長時間実行されるC関数はOSスレッドを完全にブロックします。

第五に、Go/C間のABI変換に伴う関数呼び出しのオーバーヘッドが発生します。

# オーバーヘッドの規模

1回のcgo呼び出しには約50から100ナノ秒のオーバーヘッドがかかります。純粋なGo関数呼び出しが約1から2ナノ秒であることと比較すると、約50倍のコストになります。

# 推奨されるパターン

ホットループ内で1要素ずつcgoを呼び出すのは避けるべきです。代わりに、バッチ処理としてC側でまとめて処理するパターンが推奨されます。BatchSimulateCgoBoundary関数ではOSスレッドの固定を1回だけ行い、全要素をまとめて処理しています。

# ベンチマークの実行方法

以下のコマンドで純粋なGo関数とシミュレーション関数の性能差を比較できます。

```
go test -bench=. ./29_cgo_overhead/...
```

# テストの実行方法

以下のコマンドでテストを実行できます。

```
go test -v ./29_cgo_overhead/...
```
