# happens-before関係

Goのメモリモデルにおいて、happens-before関係はある操作の結果が別の操作から確実に見えることを保証する順序規則です。
この関係が成立しない場合、コンパイラやCPUによる最適化で操作の順序が入れ替わる可能性があります。

# Mutexによる順序保証

sync.MutexのUnlockは、同じMutexに対する次のLockよりも前に発生します。
この性質により、ロック区間内で行った書き込みは次にロックを取得したゴルーチンから確実に見えます。

MutexOrder関数では、n個のゴルーチンが同じMutexでカウンタをインクリメントします。
happens-before関係が連鎖するため、最終的なカウンタの値は必ずnになります。

# チャネルによる順序保証

バッファなしチャネルへの送信は、対応する受信よりも前に発生します。
ChannelOrder関数では、この性質を利用してゴルーチン間で値を安全に受け渡しています。

# アトミック操作による順序保証

sync/atomicパッケージの操作は、対象のメモリ位置に対してhappens-before関係を構築します。
AtomicOrder関数では、atomic.AddInt64を使って複数のゴルーチンからカウンタを安全にインクリメントしています。

# WaitGroupによる順序保証

WaitGroupのDone呼び出しは、対応するWait呼び出しの完了よりも前に発生します。
WaitGroupOrder関数では、すべてのゴルーチンがDoneを呼んでからWaitが返るため、結果のスライスにはn個の要素が含まれます。
