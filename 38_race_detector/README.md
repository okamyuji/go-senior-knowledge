# Goのレースディテクタ

Goのレースディテクタは、プログラム実行時にデータ競合を検出するツールです。
コンパイル時にメモリアクセスの計測コードを挿入し、実行時に非同期な読み書きの衝突を監視します。

# レースディテクタの使い方

-raceフラグを付けてビルドまたはテストを実行すると、レースディテクタが有効になります。
go test -raceでテスト中のデータ競合を検出でき、go build -raceで計測付きバイナリを生成できます。
データ競合が検出されると、競合しているゴルーチンのスタックトレースが出力されます。

# レースディテクタの制限

レースディテクタは実行時に実際に発生したデータ競合のみを検出します。
特定の実行パスやタイミングで発生しなかった潜在的な競合は検出できません。
したがって、レースディテクタで問題が報告されなくても、プログラムにデータ競合がないことは証明できません。

# パフォーマンスへの影響

レースディテクタはサンプリングベースで動作し、CPUとメモリの両方に約5-10倍のオーバーヘッドが生じます。
この負荷のため、本番環境での使用は推奨されません。
テストやCI環境で定期的に-raceフラグ付きテストを実行することが推奨されます。

# Mutexによる安全なインクリメント

SafeIncrement関数では、sync.Mutexを使って共有カウンタへのアクセスを排他制御しています。
各ゴルーチンがロックを取得してからカウンタを更新し、更新後にロックを解放します。
この方式は理解しやすく、少数回のアクセスでは十分な性能を発揮します。

# atomicによる安全なインクリメント

SafeAtomicIncrement関数では、sync/atomicパッケージのInt64型を使ってロックなしでカウンタを更新しています。
アトミック操作はMutexよりも軽量で、単純なカウンタのインクリメントのような操作に適しています。
ただし、複数のフィールドを一貫性を保って更新する必要がある場合にはMutexが適切です。

# チャネルによる安全な通信

SafeChannelCommunication関数では、共有メモリを使わずにチャネルを通じてデータを受け渡しています。
各プロデューサゴルーチンが値をチャネルに送信し、コンシューマがチャネルから受信して集計します。
Goの方針である「メモリの共有ではなく、通信によってメモリを共有する」を実践しています。

# テストの実行方法

以下のコマンドでレースディテクタ付きのテストを実行できます。

```
go test -race -v ./38_race_detector/...
```
