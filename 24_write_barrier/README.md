# ライトバリア

ライトバリアは、GCの並行マーキング中にヒープ上のポインタ書き込みを追跡するための仕組みです。
コンパイラがヒープ上のポインタ書き込み箇所にコードを挿入し、GCに通知します。

# ライトバリアが必要な理由

並行GCではマーキングとアプリケーションの実行が同時に進行します。
ライトバリアがなければ、走査済み(黒)のオブジェクトから未走査(白)のオブジェクトへの新しい参照を見落とす可能性があります。
その結果、到達可能なオブジェクトが誤って回収されることを防ぐため、ライトバリアがポインタの書き込みを記録します。

# ポインタの書き込み

PointerWrite関数は、Node構造体のNextフィールドにポインタを書き込みます。
Nodeがヒープにエスケープすると、GCの並行マーキング中にこのポインタ書き込みでライトバリアが発動します。

# ヒープ上の参照チェーン

HeapReference関数は、n個のノードが互いに参照し合うリンクリストを作成します。
各ノードのNextポインタが次のノードを指しており、すべての参照がヒープ上に存在します。
ChainLength関数でリストを走査してノード数を検証できます。

# スタックとヒープの比較

StackVsHeap関数は、スタック上に留まる変数とヒープにエスケープする変数の違いを示しています。
スタック上のポインタ操作ではライトバリアが不要です。STWフェーズでスタックが一括走査されるためです。
ヒープにエスケープするポインタ書き込みではライトバリアが必要になり、数ナノ秒のオーバーヘッドが発生します。

# パフォーマンスへの影響

ライトバリアはGCがアクティブな間、ヒープ上のポインタ書き込みごとに小さなオーバーヘッドを追加します。
go build -gcflags="-m"を使うと、どの変数がヒープにエスケープするかを確認できます。
スタック割り当てがヒープ割り当てより高速な理由の一つが、このライトバリアの有無にあります。
