# スライスの内部構造

Goのスライスは、内部的に3つのフィールドを持つヘッダ構造体として表現されています。
背後の配列へのポインタ、長さ(len)、容量(cap)の3つで構成されます。

# スライスヘッダ

SliceHeader関数は、渡されたスライスのlenとcapを返します。
nilスライスの場合、lenとcapはどちらも0になります。
make([]int, 3, 10)のように作成したスライスでは、lenが3、capが10として報告されます。

# appendの容量拡張

appendで要素を追加する際、背後の配列に空きがなければ新しい配列が確保されます。
小さいスライスでは容量がおよそ2倍に拡張され、256要素を超えるあたりから約1.25倍の拡張率に変わります。
AppendGrowth関数では、nilスライスにn個の要素を追加しながら、各ステップの容量を記録しています。

# 背後の配列の共有

スライス式(s[low:high])で作成したサブスライスは、元のスライスと同じ背後の配列を共有します。
そのため、一方のスライスで要素を変更すると、もう一方にも反映されます。
SharedBackingArray関数では、サブスライスへの書き込みが元のスライスに影響することを示しています。

# 独立したコピーの作成

組み込みのcopy関数を使うことで、背後の配列を共有しない独立したスライスを作成できます。
CopySlice関数では、makeで新しいスライスを確保してからcopyで値を転写しています。
コピー先を変更しても元のスライスには影響しません。

# テストの実行方法
