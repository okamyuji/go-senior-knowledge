# 文字列とバイトスライスの関係

Goの文字列はイミュータブルなバイト列として内部的に表現されています。
文字列と[]byteの相互変換ではコピーが発生し、それぞれ独立したメモリ領域を持ちます。

# 文字列からバイトスライスへの変換

StringToBytes関数は、文字列を[]byteに変換します。
この変換では新しいバッキング配列が確保され、文字列のバイトがコピーされます。
変換後のバイトスライスを変更しても、元の文字列には影響しません。

# バイトスライスから文字列への変換

BytesToString関数は、[]byteを文字列に変換します。
この変換でもコピーが発生するため、変換後に元のバイトスライスを変更しても文字列は変化しません。
コピーが発生する理由は、文字列のイミュータビリティを保証するためです。

# 文字列のイミュータビリティ

Goでは文字列の個々のバイトに代入することはコンパイルエラーになります。
文字列を「変更」するには、[]byteに変換してから変更を加え、再び文字列に戻す必要があります。
StringImmutability関数がこの手順を実装しています。

# ルーンによるイテレーション

range式で文字列をイテレートすると、バイト単位ではなくルーン(Unicodeコードポイント)単位で処理されます。
日本語の漢字や絵文字のようなマルチバイト文字も、1つのルーンとしてカウントされます。
RuneIteration関数は文字列からルーンのスライスを返し、RuneCount関数はルーン数を返します。

# unsafeによる変換

unsafe.Stringやunsafe.SliceDataを使うと、コピーなしで文字列とバイトスライスを変換できます。
ただし、この方法は文字列のイミュータビリティ保証を破壊するため、未定義動作を引き起こす可能性があります。
標準ライブラリ内部では安全性を保証した上で使用していますが、アプリケーションコードでは使用すべきではありません。

# テストの実行方法
