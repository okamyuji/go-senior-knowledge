# パッケージ初期化順序

## 概要

Goではパッケージの初期化が厳密に定められた順序で行われます。パッケージレベル変数の初期化、init関数の実行、そしてmain関数の呼び出しという流れを正しく理解することが、予期しない挙動を防ぐために重要です。

## 初期化の流れ

パッケージの初期化は以下の順序で実行されます。

1. インポートされたパッケージが先に初期化されます(依存関係順)
2. パッケージレベル変数がソースコード上の宣言順に初期化されます
3. init関数がソースコード上の宣言順に実行されます
4. mainパッケージの場合、最後にmain関数が呼び出されます

## パッケージレベル変数の順序

同一ファイル内のパッケージレベル変数は、宣言された順序で初期化されます。変数の初期化式に副作用がある場合、この順序が動作に影響を与えます。

```go
var first = recordVar("var_first")   // 最初に実行されます
var second = recordVar("var_second") // 次に実行されます
```

## 複数のinit関数

同一ファイル内に複数のinit関数を定義することができます。これらは宣言順に実行されます。ただし、同一パッケージ内の異なるファイルに定義されたinit関数の実行順序は、ファイル名の辞書順に依存します。

init関数はユーザーコードから直接呼び出すことはできません。

## よくある落とし穴

### init関数での副作用

init関数内でデータベース接続やファイルオープンなどの副作用を実行すると、テストが難しくなります。初期化に失敗した場合、panicが発生して原因の特定が困難になることがあります。可能であれば、このような処理はmain関数や明示的な初期化関数に移動してください。

### 循環インポート

パッケージAがパッケージBをインポートし、パッケージBもパッケージAをインポートする循環依存は、コンパイルエラーになります。init関数の依存関係は暗黙的になりやすいため、パッケージ設計の段階で依存の方向を整理してください。

### init関数の肥大化

init関数に多くの処理を詰め込むと、プログラムの起動時間が長くなります。init関数はシンプルに保ち、重い処理は遅延初期化(sync.Onceなど)で実行することを推奨します。
