# ビルドタグ

## 概要

Goのビルドタグ(ビルド制約)は、コンパイル時にどのファイルをパッケージに含めるかを制御する仕組みです。OS固有の実装やカスタム機能の切り替えに使用されます。このパッケージでは、ビルドタグの構文、使い方、そして注意点を解説します。

## 構文

Go 1.17以降では、//go:buildディレクティブを使用します。

```go
//go:build linux && amd64
```

旧構文の// +buildも引き続きサポートされていますが、新しいコードでは//go:buildの使用が推奨されています。

```go
// +build linux,amd64
```

//go:build行はpackage宣言の前に記述し、//go:build行とpackage宣言の間には空行を入れる必要があります。空行を忘れると、制約は通常のコメントとして無視されます。

## よく使われるタグ

OS指定にはlinux, darwin, windows, freebsdなどが使えます。アーキテクチャ指定にはamd64, arm64, 386などが使えます。これらを論理演算子(&&, ||, !)で組み合わせることができます。

```go
//go:build (linux || darwin) && amd64
```

-tagsフラグを使うと、カスタムタグでビルドを制御できます。

```
go build -tags mytag ./...
```

## ファイルの構成パターン

プラットフォーム固有の実装を提供する場合、同じ関数シグネチャを持つ複数のファイルを用意します。

- build_tags_linux.goにはlinux向けの実装を記述します
- build_tags_darwin.goにはmacOS向けの実装を記述します
- build_tags_default.goにはデフォルトの実装を記述します

コンパイル時にビルドタグに一致するファイルだけが含まれるため、同じ関数名が複数のファイルに存在してもコンパイルエラーにはなりません。

## 注意点

### 暗黙的な振る舞いの変化

ビルドタグによって含まれるファイルが変わると、プログラムの挙動も静かに変化します。コンパイルエラーにならないため、特定のプラットフォームでのみ発生するバグの原因になることがあります。

### runtime.GOOSとの使い分け

単にOS名を判定するだけであれば、ビルドタグではなくruntime.GOOSを実行時に参照する方法もあります。ビルドタグはコンパイル時にファイル単位で切り替わるのに対し、runtime.GOOSは実行時に分岐する点が異なります。

OS固有のシステムコールやCライブラリに依存するコードはビルドタグで分離してください。単純な文字列の出し分け程度であれば、runtime.GOOSを使う方がシンプルです。

### ファイル名による暗黙のタグ

Goコンパイラはファイル名にOSやアーキテクチャ名が含まれている場合、暗黙的にビルド制約として扱います。例えば、file_linux.goはlinuxビルドでのみコンパイルされます。この規則を知らずにファイル名を付けると、意図せずファイルが除外されることがあります。
