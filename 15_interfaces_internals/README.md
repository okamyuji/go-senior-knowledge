# インターフェースの内部構造

## 概要

Goのインターフェース値は内部的に2つのポインタで構成されています。1つは型情報へのポインタで、もう1つは実際のデータへのポインタです。この構造を理解することで、nilインターフェースの振る舞いや動的ディスパッチの仕組みを正しく把握できます。

## nilインターフェースとnilポインタを保持するインターフェースの違い

nilインターフェースは型情報もデータも持たない状態です。一方、nilポインタを保持するインターフェースは型情報を持つためnilではありません。

```go
var s Stringer          // s == nil は true になります
var d *Dog = nil
s = d                   // s == nil は false になります
```

この違いはエラーハンドリングなどで意図しないバグの原因になりやすいため、注意が必要です。

## インターフェースの比較

2つのインターフェース値は、動的な型が同じで、かつ動的な値が等しい場合にのみ等しくなります。型が異なれば値が同じでも等しくなりません。nilインターフェース同士は等しくなります。

## 動的ディスパッチ

インターフェースを通じてメソッドを呼び出すと、実行時に格納されている動的な型に基づいて適切なメソッドが選択されます。これが動的ディスパッチです。

## 型情報の取得

fmt.Sprintfの%Tフォーマットやreflect.TypeOfを使うことで、インターフェースに格納されている動的な型を確認できます。

## ファイル構成

- interfaces.go: nilインターフェースの区別、インターフェースの比較、動的ディスパッチ、型情報の取得を実装しています
- interfaces_test.go: nilインターフェースとnilポインタの違い、型が異なるインターフェースの比較、動的ディスパッチの動作を検証しています
