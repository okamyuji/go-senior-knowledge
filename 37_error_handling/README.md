# Goのエラーハンドリング

Goではエラーをerrorインターフェースの値として扱い、明示的に返却・検査する方式を採用しています。
例外機構を使わずにエラーを制御できるため、エラーの伝播経路がコード上で明確になります。

# センチネルエラー

センチネルエラーはパッケージレベルで定義されるerror値で、errors.Newで作成します。
ErrNotFoundやErrPermissionのようにエラーの種類を表す定数として使い、呼び出し側がerrors.Isで比較します。
同一のerror値をアイデンティティ(ポインタ)で比較するため、文字列比較よりも安全に判定できます。

# エラーのラップ

fmt.Errorfに%w動詞を指定すると、元のエラーを内部に保持した新しいエラーを生成できます。
ラップされたエラーには追加のコンテキスト情報が付与されるため、デバッグ時にエラーの発生経路を追跡しやすくなります。
何重にラップしても元のエラーはチェーン内に保持されます。

# errors.Isによるチェーン検査

errors.Isはエラーチェーンを再帰的にたどり、指定したターゲットが含まれているかを判定します。
ラップされたエラーに対しても正しく動作するため、センチネルエラーの検査には常にerrors.Isを使うべきです。
直接の等値比較(==)ではラップされたエラーを検出できません。

# errors.Asによる型抽出

errors.Asはエラーチェーンから特定の型のエラーを取り出します。
カスタムエラー型に含まれるフィールド情報(フィールド名やメッセージなど)にアクセスしたい場合に使用します。
ターゲット変数へのポインタを渡すことで、マッチした型の値が格納されます。

# カスタムエラー型

errorインターフェースを実装した独自の構造体を定義することで、エラーに追加情報を持たせることができます。
ValidationErrorではフィールド名とメッセージを保持し、Error()メソッドで人間が読める形式の文字列を返します。
fmt.Errorfの%wで包めば、errors.Asで後から取り出すこともできます。
