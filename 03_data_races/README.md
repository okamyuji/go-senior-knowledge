# データ競合

データ競合とは、2つ以上のゴルーチンが同じ変数に同時にアクセスし、そのうち少なくとも1つが書き込みである場合に発生します。
Goのメモリモデルでは、データ競合が存在するプログラムの動作は未定義とされています。

# Mutexによる安全なカウンタ

SafeCounter関数は、sync.Mutexを使ってカウンタへのアクセスを排他制御しています。
ロック区間内では1つのゴルーチンだけがカウンタにアクセスするため、データ競合は発生しません。
n個のゴルーチンがそれぞれ1回インクリメントするので、最終値は常にnになります。

# アトミック操作による安全なカウンタ

SafeAtomicCounter関数は、sync/atomicパッケージのAddInt64を使っています。
アトミック操作はハードウェアレベルで不可分性が保証されるため、Mutexなしでもデータ競合を防げます。
Mutexよりもオーバーヘッドが小さいため、単純なカウンタにはアトミック操作が適しています。

# 非同期アクセスが危険な理由

UnsafePatternDemo関数は、同期なしの並行アクセスがなぜ問題になるかを説明する文字列を返します。
実際にデータ競合を起こすコードは含んでいません。

同期なしにゴルーチン間で変数を共有すると、コンパイラやCPUの最適化によって書き込みの順序が変わったり、書き込み自体が他のゴルーチンから見えなくなったりします。
go testに-raceフラグを付けると、データ競合を検出できます。

# テストの実行方法

以下のコマンドでテストを実行できます。

```
go test -v ./03_data_races/...
```
