# JSON処理の落とし穴

## 概要

Goのencoding/jsonパッケージは手軽に使えますが、いくつかの挙動が直感に反するため注意が必要です。このパッケージでは、数値の精度損失、omitemptyの挙動、非公開フィールドの無視という3つの代表的な落とし穴を解説します。

## 数値の精度損失

json.Unmarshalでinterface{}に数値をデコードすると、Go側ではfloat64として格納されます。float64はIEEE 754の64ビット浮動小数点数であり、2の53乗を超える整数は正確に表現できません。

例えば、9007199254740993(2の53乗+1)をfloat64に変換すると、9007199254740992に丸められます。APIレスポンスに大きなIDが含まれる場合、この精度損失がバグの原因になります。

## UseNumberによる精度の維持

json.NewDecoderのUseNumberメソッドを有効にすると、数値はfloat64ではなくjson.Number型(文字列ベース)として格納されます。json.NumberのInt64メソッドやString メソッドを使うことで、元の値を正確に取り出すことができます。

```go
dec := json.NewDecoder(reader)
dec.UseNumber()
```

大きな整数を扱う可能性がある場合は、常にUseNumberの使用を検討してください。

## omitemptyの挙動

構造体タグにomitemptyを付けると、フィールドがゼロ値のとき JSON出力から省略されます。各型のゼロ値は以下の通りです。

- 数値型は0が該当します
- 文字列型は空文字列が該当します
- bool型はfalseが該当します
- ポインタ型はnilが該当します

注意すべき点として、ポインタが指す先がゼロ値であっても、ポインタ自体がnilでなければ省略されません。つまり、int型のゼロを指すポインタはJSON出力に含まれます。

## 非公開フィールドの無視

encoding/jsonは、小文字で始まる非公開フィールドを完全に無視します。jsonタグを付けていても、非公開フィールドはエンコード時に出力されず、デコード時にも値が設定されません。

構造体のフィールドがJSONに現れない場合、まずフィールド名が大文字で始まっているかを確認してください。これはGoのJSON処理で最もよくあるミスの一つです。

## 対策のまとめ

大きな整数を含むJSONを扱うときは、json.NewDecoderとUseNumberを併用してください。omitemptyをつけたフィールドのゼロ値の挙動は型ごとに異なるため、ポインタ型との組み合わせには特に注意が必要です。JSONに含めたいフィールドは必ずエクスポート(大文字始まり)にしてください。
