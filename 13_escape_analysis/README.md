# エスケープ解析とスタック/ヒープ割り当て

## 概要

Goコンパイラはエスケープ解析を行い、変数をスタックに割り当てるかヒープに割り当てるかを自動的に決定します。スタック割り当ては関数の終了時に自動で解放されるため、GCの負荷がかかりません。変数が関数のスコープを超えて参照される場合、コンパイラはその変数をヒープに割り当てます。

## エスケープ解析の確認方法

以下のコマンドでコンパイラのエスケープ解析結果を確認できます。

```
go build -gcflags="-m" ./13_escape_analysis/
```

-mフラグを複数回指定すると、より詳細な情報が表示されます。

## スタックに留まるケース

関数内でのみ使用され、外部に参照が渡されない変数はスタックに割り当てられます。StackAlloc関数では、ローカル変数sumが関数内でのみ使われるため、スタック上に配置されます。

## ヒープにエスケープするケース

HeapAlloc関数のようにローカル変数のポインタを返す場合、その変数は関数のスタックフレームよりも長く生存する必要があるため、ヒープに割り当てられます。SliceEscape関数でスライスを返す場合も、背後の配列がヒープにエスケープします。

## ポインタを渡してもエスケープしないケース

NoEscape関数のように、ポインタを受け取っても保存や返却をしない場合、コンパイラはエスケープが不要であると判断します。この場合、呼び出し元は変数をスタックに割り当てることができます。

## ファイル構成

- escape_analysis.go: スタック割り当て、ヒープ割り当て、スライスのエスケープ、エスケープしないポインタ渡しを実装しています
- escape_analysis_test.go: 各関数の動作を検証し、ベンチマークでスタック割り当てとヒープ割り当ての性能差を比較しています
