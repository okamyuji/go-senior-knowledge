# mapの並行アクセス

Goの通常のmapは並行安全ではありません。
複数のゴルーチンから同時に読み書きすると、ランタイムがデータ競合を検出してプログラムを強制終了させます。
これは通常のpanicではなくfatalエラーであるため、recoverで捕捉することはできません。

# sync.RWMutexを使ったスレッドセーフなmap

SafeMapはsync.RWMutexでmapへのアクセスを保護するラッパー構造体です。
読み取り操作にはRLockを使い、複数のゴルーチンが同時に読み取れるようにしています。
書き込み操作にはLockを使い、排他的なアクセスを保証しています。

この方法は実装がシンプルで、読み取りが多く書き込みが少ないワークロードに適しています。
Store、Load、Delete、Lenの各メソッドが適切にロックを取得・解放しています。

# sync.Mapの使い方

sync.Mapは標準ライブラリが提供する並行安全なmap実装です。
Store、Load、Delete、Rangeの各メソッドを使って操作します。

sync.Mapは以下のような特定のユースケースに最適化されています。
キーが一度書き込まれた後は主に読み取られるケースと、多数のゴルーチンが重複しないキーセットを読み書きするケースです。
汎用的な用途ではRWMutexを使ったラッパーの方がパフォーマンスが良い場合があります。

# 通常のmapの並行アクセスによるクラッシュ

通常のmapに対して複数のゴルーチンから同時に読み書きを行うと、ランタイムが検出してfatalエラーを発生させます。
エラーメッセージは「concurrent map read and map write」や「concurrent map writes」になります。
これは単なるデータ競合ではなく、プログラムの即時強制終了を引き起こします。
mapを並行アクセスする場合は、必ずsync.RWMutexかsync.Mapを使用してください。

# テストの実行方法

以下のコマンドでテストを実行できます。

```
go test -v -race ./20_map_concurrency/...
```
