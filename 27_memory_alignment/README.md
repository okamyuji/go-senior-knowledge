# メモリアラインメントとフォールスシェアリング

Goコンパイラは構造体のフィールドをそれぞれのサイズに応じた境界に配置します。この配置制約を満たすためにフィールド間にパディングバイトが挿入されます。

# アラインメントの基本ルール

各フィールドは自身のサイズの倍数のアドレスに配置されます。int64は8バイト境界、int32は4バイト境界、boolは1バイト境界に配置されます。構造体全体のサイズは最大アラインメントの倍数に切り上げられます。

# 悪いレイアウトと良いレイアウト

BadLayout構造体ではboolとint64を交互に配置しているため、各boolの後に7バイトのパディングが発生します。合計サイズは32バイトになります。

GoodLayout構造体ではint64を先に配置し、boolを末尾にまとめています。パディングは末尾の6バイトだけで済むため、合計サイズは24バイトに削減されます。

一般的に、フィールドをサイズの大きい順に並べるとパディングを最小化できます。

# フォールスシェアリング

フォールスシェアリングは、独立してアクセスされる変数が同一のCPUキャッシュライン上に存在する場合に発生します。一方のコアが変数を更新すると、同じキャッシュライン上の別の変数しか使わない他のコアでもキャッシュが無効化されます。

PaddedPair構造体では2つのカウンタの間にパディングを挿入して別々のキャッシュラインに配置しています。これにより、並行アクセス時のキャッシュ無効化を防止できます。

# テストの実行方法

```
go test -v ./27_memory_alignment/...
```
