# http.Transportのカスタマイズ

net/httpパッケージのTransportとClientを適切に設定することで、本番環境での接続管理とタイムアウト制御を最適化できます。

# コネクションプーリング

http.Transportはスキームとホストの組み合わせをキーとしてアイドル接続のプールを管理しています。接続を再利用することで、TCPハンドシェイクやTLSネゴシエーションのコストを回避できます。

MaxIdleConnsはプール全体のアイドル接続数の上限を設定します。MaxIdleConnsPerHostは1ホストあたりのアイドル接続数の上限を設定します。デフォルト値は2ですが、単一のバックエンドに高スループットで通信する場合は不足します。

# Keep-Alive

HTTP/1.1ではデフォルトで接続がKeep-Aliveされます。IdleConnTimeoutで指定した期間を超えてアイドル状態が続いた接続は自動的にクローズされます。

DisableKeepAlivesをtrueにするとリクエストごとに新しい接続を作成しますが、パフォーマンスに大きな影響があるためテスト以外では推奨しません。

# タイムアウトの階層構造

http.Clientには複数のタイムアウト設定があり、それぞれ異なる障害から保護します。

DialContextのTimeoutはTCP接続の確立を制御します。リモートホストが到達不能な場合にここでタイムアウトします。

TLSHandshakeTimeoutはTLSネゴシエーションの制限時間を設定します。

ResponseHeaderTimeoutはリクエスト送信後からレスポンスヘッダ受信までの制限時間を設定します。サーバーが接続を受け入れたが応答が遅い場合にここでタイムアウトします。

Client.Timeoutはリクエスト全体の制限時間です。接続確立からレスポンスボディの読み取り完了まで全てを含みます。

# テストの実行方法

以下のコマンドでテストを実行できます。

