# mapの内部動作

Goのmapはハッシュテーブルとして実装されており、キーと値のペアを効率的に格納・検索できます。
内部的にはバケットの配列で構成されており、要素数に応じて自動的にリハッシュと拡張が行われます。

# 基本操作(CRUD)

BasicMapOps関数では、make関数でmapを作成し、挿入、更新、削除の基本操作を行っています。
MapLookup関数では、comma-okイディオムを使ってキーの存在確認と値の取得を同時に行います。
okがfalseの場合、値は型のゼロ値になります。

# イテレーション順序の非決定性

Goのmapはイテレーション順序が保証されていません。
IterationOrder関数で同一のmapを複数回イテレーションすると、キーの出現順序が異なる可能性があります。
これはGoランタイムが意図的にイテレーション順序をランダム化しているためです。
順序に依存したコードを書くとバグの原因になるため、必要に応じてキーをソートしてください。

# mapの動的成長

MapGrowth関数では、mapに大量のエントリを追加しています。
mapはスライスと異なりcapの概念が外部に公開されていませんが、内部で自動的にバケット数を増やして対応します。
make(map[K]V, hint)のように初期容量のヒントを渡すことで、頻繁なリハッシュを避けることができます。

# nilマップの動作

NilMapRead関数では、nilマップからの読み取りがゼロ値を返すことを示しています。
この操作はpanicせずに安全に実行されます。

一方、NilMapWrite関数のようにnilマップへの書き込みを行うとpanicが発生します。
mapを使う前にmake関数で初期化するか、リテラル構文で作成する必要があります。
