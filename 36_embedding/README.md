# Goの構造体埋め込み

Goの構造体埋め込み(embedding)は、あるstructの中に別のstructをフィールド名なしで配置する仕組みです。
埋め込まれた型のメソッドやフィールドは外側の型に昇格(promote)され、直接アクセスできるようになります。

# メソッドの昇格

構造体にLogger型を埋め込むと、Logger.Logメソッドが外側の構造体から直接呼び出せるようになります。
Service構造体はLoggerとCounterを埋め込んでいるため、s.Log()やs.Increment()を直接呼び出すことができます。
ただし、メソッドのレシーバは埋め込まれた型のままであり、外側の型にはなりません。

# 曖昧性の解決

2つの埋め込み型が同名のメソッドを持つ場合、外側の構造体から直接呼び出すとコンパイルエラーになります。
この例ではReaderとWriterがどちらもDescribeメソッドを持っているため、ReadWriterが自身のDescribeメソッドを定義して曖昧性を解決しています。
個別の埋め込み型のメソッドにはrw.Reader.Describe()のように明示的にアクセスすることもできます。

# ゼロ値での利用

埋め込み構造体はゼロ値の状態でも利用可能です。
Serviceをvar宣言で初期化した場合、LoggerのPrefixは空文字列になりますが、Logメソッドは正常に動作します。
Counterのフィールドも0で初期化されるため、そのままIncrementを呼び出すことができます。

# 埋め込みと継承の違い

Goの埋め込みはコンポジション(合成)であり、クラスベースの継承とは異なります。
継承では基底クラスのメソッドを派生クラスがオーバーライドし、レシーバが派生クラスに変わります。
一方、Goの埋め込みでは昇格されたメソッドのレシーバは埋め込まれた型のままであり、外側の型を認識しません。

# インターフェースの自動的な充足

型を埋め込むことで、外側の型がインターフェースを自動的に満たすようになります。
Name型がStringメソッドを持っている場合、Nameを埋め込んだPerson型もStringerインターフェースを満たします。
これにより、明示的にメソッドを再定義せずにインターフェースの要件を満たすことができます。
