# atomic, Mutex, channelの比較

Goで並行処理の同期を行う方法は主に3つあります。それぞれの特性を理解して適切に使い分けることが重要です。

# atomic操作

sync/atomicパッケージはロックフリーの数値操作を提供します。単一の変数に対するインクリメントやCompare-And-Swapなど、1回の読み書きで完結する操作に適しています。AtomicCounter関数ではatomic.AddInt64を使って複数のゴルーチンから安全にカウンタを加算しています。

atomic操作はMutexよりオーバーヘッドが小さいですが、複数の変数にまたがる不変条件を保護することはできません。

# sync.Mutex

sync.Mutexは任意のコードブロックを排他制御できます。複数の変数を同時に更新する場合や、条件チェックと書き込みをアトミックに行う場合に使用します。MutexCounter関数ではLockとUnlockの間でカウンタをインクリメントしています。

Mutexの使い方として、deferでUnlockを呼ぶパターンが推奨されます。パニックが発生してもデッドロックを防げるためです。

# チャネルによる同期

チャネルはGoの並行処理において通信によるデータ共有を実現します。ChannelCounter関数では、インクリメント要求をチャネルで送信し、単一の管理ゴルーチンがカウンタの状態を所有しています。

チャネルは単純なカウンタにはオーバーヘッドが大きいですが、状態の所有者が副作用を伴う処理や複数のワークフローの調整を行う場合に適しています。

# 使い分けの指針

単純な数値カウンタやフラグにはatomicを使います。複数の変数を保護する必要がある場合や複雑な不変条件がある場合はMutexを使います。ゴルーチン間でデータを受け渡しながら処理を進める場合はチャネルを使います。
